## 2. 架构:三铁律 + 数据流

**三铁律(改任何机制前必对照)**:
1. **极简底层**:几个国势 + 几股势力 + 人物 + 危机。深度来自**联动**,不来自堆维度。
2. **LLM 只当「嘴」与「裁判」**,代码管状态机与数值。单层,**绝不反向从叙事抠数字**。
3. **信息不全 / 君命直贯 / 没有最优解 / 后果连锁**,从第一刀就缝进去。

**数据流(一个月的回合)**:
```
玩家召见大臣 → llm.summon() 扮演大臣口吻奏对(80-180字,不报数值、不出戏)
玩家下旨 → 退朝·推演 → llm.adjudicate() 输出 JSON:
    { narrative:邸报叙事, resolved:bool, effects:[{target,direction,magnitude,reason}] }
    —— LLM 只给「方向 + 档位(微/轻/中/大/极)」,不给具体数字
engine.apply_effects() 把档位→数值:MAGNITUDE={微:3,轻:6,中:12,大:22,极:40},clamp 0-100
危机 resolved → next_from_pool() 从事件池取下一个危机接棒(事件驱动)
```

**国势 6 维**:`国库 / 皇威 / 民心 / 朝堂 / 耳目 / 边事`(0-100)。**「耳目」=皇帝情报力**——诛厂卫会掉它,掉到 <40 时后续危机的奏报(brief)自动加迷雾前缀,但裁判仍握真相(信息不全机制化)。

**危机的 brief vs truth**:`brief`=皇帝所知(可能被粉饰/起雾,给玩家看);`truth`=真相(只喂裁判 LLM,**永不发给前端**)。

**cast 机制**:`Crisis.cast` 是一个 **flat list of 实体 id**(如 `["guanning","liaodong","houjin"]`),指向真实的地区/军队/势力。`world.backdrop(cast)` 把它们渲染成「天下实况」只读事实表,注入裁判/召对的提示上下文。**characters/factions 不进 cast**(它们本就活在 state)。纯朝堂危机 cast 留空即可。
